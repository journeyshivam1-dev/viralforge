# ViralForge — Phase 2 Plan: zero-touch daily automation

**Date:** 2026-09-30 · **Owner decisions captured from operator Q&A** · Read `HANDOFF.md` first.

## Target

Every day, without human input:

- 5 niches — `cartoon`, `food`, `health`, `tech`, `edtech` — each with its own profile (1 Instagram Business account + 1 Facebook Page).
- 5 posts per niche per day = **25 content items/day**, each published to **both** IG and FB.
- Mix per niche per day: **3 reels** (image slideshow + Hindi TTS + subtitles), **1 carousel**, **1 single image**.
- System picks posting slots in IST.
- Publish mode per niche: `manual_approval` (**default**, one-tap approve on Telegram or dashboard) or `immediate_auto` (fully automatic at the slot).
- Local first: everything runs end-to-end with `PUBLISHING_DISABLED=true`. Real posting later via a public media URL (Cloudflare Tunnel / ngrok, or Vercel/hosted storage).

## Guiding rules (unchanged from Phase 1)

- PostgreSQL is the source of truth; BullMQ only transports. Every new automated action goes through `enqueue_pipeline_attempt` / outbox rows.
- Missing config → **block**, never fail.
- A retry resumes the failed stage only. Completed stage outputs on the content row are never regenerated by a retry.

## Slices (each ships green: unit tests, pgTAP, build)

### S1 — Retry semantics, "retry all failed", failure alerts
- Stage retry budget = **4 attempts with exponential backoff** for research/generation/media/rendering/validation. Publishing stays at 1 BullMQ attempt (DB-reconciled) to avoid double posts.
- Fix: scheduler must **not** call `start_content_pipeline` for items that already have a failed run (that restarts from research and regenerates everything). It resumes the existing run from its failed stage.
- New RPC `retry_failed_pipelines(org, requested_by)` → for every `failed`/`blocked` run, re-enqueue only its `current_stage`. API `POST /api/pipeline-runs/retry-failed` + dashboard button.
- Media stage already reuses checkpointed scene artifacts; extend the same idea to TTS clips.
- New `notification_outbox` table + `notifications` worker. On `permanent_failed` (and on `blocked`), enqueue one alert per channel: **Telegram** (Bot API `sendMessage`) and **WhatsApp** (Cloud API template/text). Deduped per attempt.

### S2 — AI provider chain: Omniroute → Gemini fallback
- `AiProviderChain` in `packages/domain`: text, image, TTS, video. Each capability tries Omniroute first, then Gemini; errors classified `retryable | permanent | blocked` like `MediaProviderError`.
- Omniroute (`OMNIROUTE_BASE_URL=http://192.168.31.13:20128`): `/v1/chat/completions`, `/v1/images/generations`, `/v1/audio/speech`, video endpoint (currently times out → per-capability timeout + async poll; if it still times out, fall back to image-slideshow reels, which the operator accepted).
- Gemini (`GEMINI_API_KEY`): text (`gemini-2.5-flash`), image (Imagen / `gemini-2.5-flash-image`), TTS (`gemini-2.5-flash-preview-tts`, Hindi voices).
- Replicate remains an optional third media provider if configured.
- Usage/cost per call recorded in `ai_generation_metadata.usage[]`.

### S3 — Daily planner (topics + slots)
- `niche_schedule_settings` per niche: enabled, posts/day, content mix, IST slots, publish mode, approval deadline behaviour.
- **Default IST slots** (Indian IG/FB engagement peaks): `07:30, 12:30, 17:30, 19:30, 21:30`, jittered ±10 min per niche. Reels take the evening peaks; carousel at 12:30; single image at 07:30.
- Topic sources, merged and ranked per niche:
  1. **Operator topic list / content calendar** (`topic_backlog` table; dated entries win on their date, undated entries are consumed FIFO). CSV/JSON upload + dashboard form.
  2. **Trends**: Google Trends daily trending RSS (geo=IN) and YouTube Data API `videos?chart=mostPopular&regionCode=IN` (needs `YOUTUBE_API_KEY`), filtered for relevance per niche by the LLM.
  3. **LLM ideation** fills remaining slots.
- De-duplication against the last 60 days of topics per niche (normalized title + LLM similarity check).
- `daily-planner` BullMQ repeatable job at **00:30 IST** creates 25 `content_items` with `scheduled_at`, `media_type`, `publish_mode`, and `idempotency_key = plan-{date}-{niche}-{slot}` (safe to re-run).
- The existing scheduler starts each pipeline `generation_lead_minutes` before its slot.

### S4 — Media per content type + Hindi TTS
- **Reel**: per-scene images → per-scene TTS clips → scene duration = clip length → ffmpeg slideshow (Ken Burns zoom) + subtitles + mixed voiceover (+ optional licensed music bed) → 1080×1920 mp4.
- **Carousel**: 3–7 slides, 1080×1350, text overlay rendered with ffmpeg `drawtext` (Devanagari font) → jpg set.
- **Single image**: 1080×1350 with overlay.
- Validation becomes media-type aware for all three; `ALLOW_SILENT_VIDEO` defaults to `false` once TTS works.

### S5 — Publishing to IG + FB
- Fan out one `publication_attempts` row per connected account of the niche (IG + FB); each is idempotent via the existing unique key.
- IG: reels (`media_type=REELS`), carousel (child containers), image. FB: page reels, multi-photo post, photo.
- Caption = generated caption + CTA + hashtags (≤30 IG, deduped), AI disclosure where required.
- Graph API version configurable (`META_GRAPH_VERSION`, default current).
- Access tokens encrypted at rest (AES-256-GCM, key from secret store / env); long-lived token refresh job + expiry alert.
- Public media: `PUBLIC_MEDIA_BASE_URL` (tunnel or hosted). Kill switch `PUBLISHING_DISABLED` stays authoritative.

### S6 — One-tap approval
- After validation in `manual_approval` mode: Telegram message with preview (video/images + caption) and inline **Approve / Reject / Regenerate caption** buttons; WhatsApp gets a link to the dashboard.
- Telegram callbacks verified with `X-Telegram-Bot-Api-Secret-Token` and the allow-listed user IDs.
- If not approved by slot time: keep waiting (default) or auto-approve (per-niche setting).

### S7 — Dashboard
- Today view: 25 slots × status, filter by niche/status.
- Failed/blocked list with **Retry all failed** and per-item retry-from-stage.
- Approve/Reject buttons on content detail.
- Niche settings (mode, slots, mix) and topic backlog upload.

## Not in Phase 2
Analytics-driven slot optimisation (needs Insights history), music licensing catalogue, multi-org auth.

- `.env`: `OMNIROUTE_API_KEY`, `GEMINI_API_KEY`, `YOUTUBE_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALERT_CHAT_ID`, `WHATSAPP_*`, `TOKEN_ENCRYPTION_KEY`. Never commit `.env`; production secrets go in a secret manager.
- Meta app: see `docs/META_SETUP.md` (S5).
